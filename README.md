# Grant Assistant

Пошук і оцінка грантів для українських громадських організацій. Система збирає
оголошення з двох джерел, зіставляє їх із профілем організації й пояснює кожен
висновок цитатою — з умов конкурсу та з профілю.

Головне правило продукту: система **ніколи не каже «ви прийнятні»**. Вона каже
*чому*, з доказом, і розрізняє «ні» та «ми не знаємо».

## Що потрібно

| | |
|---|---|
| Node.js | 20+ |
| Docker Desktop | для Postgres 17 із pgvector |
| Ollama | локальна модель `qwen3:4b` |

Ollama потрібен **лише для конвеєра** — класифікації, витягування грантів і
оцінки. Сам вебінтерфейс читає вже збережені дані й працює без нього.

Жодного ключа до хмарного API немає ніде. Документи організації не залишають
цієї інфраструктури — це рішення D1, і воно ж стане обіцянкою в політиці
приватності.

## Перший запуск

```bash
npm install
cp .env.example .env        # значення за замовчуванням збігаються з docker-compose

# 1. База
npm run db:up               # Postgres у docker
npm run db:migrate          # схема
npm run db:generate         # клієнт Prisma

# 2. Модель
ollama pull qwen3:4b

# 3. Дані
npx tsx packages/db/seed.ts      # тестові фікстури грантів
npm run seed:demo                # тестова організація + документи
npx tsx scripts/setup-sources.ts # адмін + два джерела, перевірка robots.txt
```

`setup-sources.ts` створює операторський обліковий запис і записує пароль у
`admin-credentials.txt`, `seed:demo` — у `test-credentials.txt`. Обидва файли в
`.gitignore`; у базі лежить лише scrypt-хеш. Повторний запуск не змінює пароль —
скрипт, який мовчки ротує облікові дані, ніхто не наважиться перезапустити.

## Щоденний запуск

```bash
npm run db:up     # якщо Docker було зупинено
ollama serve      # якщо не запущено як служба
npm run dev
```

**http://localhost:3000** → вхід на `/vhid`, облікові дані у двох txt вище.

| Обліковий запис | Куди веде |
|---|---|
| організація | `/profil`, `/mozhlyvosti`, `/hranty/[id]` |
| оператор | `/dzherela` — реєстр джерел |

Оператор навмисно **не має організації**: реєстр джерел не належить жодній НГО, а
операторський акаунт із членством поставив би чужі документи за один клік.

## Конвеєр

Чотири кроки, кожен окремо. Запускати саме в цьому порядку — кожен читає те, що
залишив попередній.

```bash
npx tsx scripts/setup-sources.ts   # 1. обхід джерел (робить і перший збір)
npx tsx scripts/classify.ts        # 2. грант це чи тендер, вакансія, курс
npx tsx scripts/extract-grants.ts  # 3. сторінка оголошення → Grant + правила
npx tsx scripts/build-feed.ts      # 4. зіставлення з профілем → стрічка
```

Крок 4 повільний і має бути: оцінка однієї пари організація×грант коштує ~80 с,
бо агент прийнятності міркує вголос — саме це тримає `UNCERTAIN` від згортання в
упевнене «так» або «ні». Тому перед кожним викликом моделі стоїть детермінований
префільтр; `build-feed.ts` друкує, що він відсіяв і **чому**, бо «відсіяно 6» і
«корпус нерелевантний» з числа виглядають однаково.

Крок 2 теж спершу пробує правила й лише потім модель: на двадцяти живих позиціях
правила вирішили сімнадцять без жодного виклику.

## Розробка

```bash
npm test              # 176 тестів; ті, що потребують Postgres, пропускаються без нього
npm run typecheck
npm run audit:tokens  # падає на будь-якому хардкоді кольору чи px поза tokens.css
npm run build

npm run smoke         # усі роути під обома акаунтами, проти піднятого dev
npm run eval          # золотий набір для матчингу
```

Корисне для діагностики:

```bash
npx tsx scripts/dump-page.ts /profil       # текст відрендереної сторінки
npx tsx scripts/inspect-items.ts FAILED    # що знайшли джерела і що з цим сталося
npx tsx scripts/snapshot-pages.ts          # статичні знімки екранів у public/_preview
```

`snapshot-pages.ts` кладе авторизовані сторінки у публічний шлях і відмовляється
працювати при `NODE_ENV=production`. Ця перевірка — єдине, що відділяє його від
обходу авторизації; у розгорнутому середовищі його бути не повинно.

## Що працює, а що ні

Готово: профіль організації з чотирма станами фактів, завантаження документів і
черга підтвердження, реєстр джерел, збір і класифікація, витягування грантів,
зіставлення, стрічка й розбір за критеріями.

У розробці — **редактор грантів**: із конкретної можливості відкривається
робоче місце, де генерується концепція, її можна доповнювати, працює асистент і
завантажуються PDF та документи донора з умовами конкурсу. Це і є решта обсягу
бети.

У меню лише два пункти. «Концепції», «Заявки» і «Вимоги донора» були трьома
окремими розділами й перестали ними бути: цю роботу не роблять узагалі, її
роблять під конкретний конкурс, тож вона живе в редакторі, а не в бічному меню.

Продукт у режимі дослідної експлуатації, і про це є плашка. Добір і оцінку
прийнятності ще не перевірено на живих даних, а умови донора з PDF система не
читає — у неї є лише текст оголошення. Тому на кожному екрані з висновком AI
стоїть маркер, а поруч із грантом — частка того, що вдалося прочитати.
